VLA Fundamentals: The LLM-Robotics Convergence

Introduction​

Vision-Language-Action (VLA) models represent the merger of three AI capabilities:

  • Vision: Understanding the physical world through cameras/sensors
  • Language: Comprehending and generating human instructions
  • Action: Executing robot behaviors in the real world

This chapter explores why VLA is transforming robotics.

The Traditional Robotics Paradigm​

Limitations of Classical Approaches​

Example Task: "Bring me a cup of coffee"

Traditional Method (Hard-coded):

def bring_coffee():
    # Engineer must explicitly program every step
    navigate_to(kitchen_location)
    if detect_cup():
        approach_cup()
        grasp_cup()
        check_grasp_success()
        navigate_to(user_location)
        handoff_cup()
    else:
        return "Cup not found"

Problems:

  • Brittle: Fails if cup is in unexpected location
  • Non-generalizable: New task = new program
  • Lacks common sense: Can't adapt to variations
  • Time-consuming: Months to develop for one task

The VLA Paradigm Shift​

How LLMs Change Robotics​

VLA Method (LLM-powered):

# Human command
user_command = "Bring me a cup of coffee"

# LLM generates plan
plan = llm.plan(user_command, robot_capabilities, scene_description)
# Output: [
#   "navigate_to(kitchen)",
#   "visual_search(object='cup')",
#   "grasp(object='cup')",
#   "navigate_to(user)",
#   "handoff()"
# ]

# Robot executes plan
execute_plan(plan)

Advantages:

  • Generalizable: Same system handles infinite tasks
  • Common sense: LLM brings world knowledge
  • Natural interface: Plain English commands
  • Rapid development: Hours, not months

Components Breakdown​

1. Vision Module (Module 3)

  • Object detection (YOLO, DINO)
  • Depth perception (stereo cameras)
  • Scene understanding (CLIP embeddings)
  • Visual SLAM (localization)

2. Language Module (This Module)

  • Speech recognition (Whisper)
  • Task planning (GPT-4, Claude)
  • Natural language understanding
  • Code generation for actions

3. Action Module (Module 2)

  • Motion planning (MoveIt 2)
  • Grasping control (IK)
  • Navigation (Nav2)
  • Low-level control (PID, impedance)

4. World Model (Shared State)

  • Semantic map (object locations)
  • Robot state (position, joint angles)
  • Task progress (which step?)
  • Environmental context

Key VLA Concepts​

1. Grounding Language in Perception​

Problem: LLMs are text-only. Robots need to connect words to physical world.

Example:

User: "Pick up the RED cup"

Grounding Process:

  1. Language: Parse "red cup" from command
  2. Vision: Run object detector → Find all cups
  3. Filter: Select cup with red color (CLIP: "a red cup")
  4. Localization: Get 3D position of red cup
  5. Action: Plan grasp motion to that position

Technical:

# Vision-Language grounding
def ground_object(description, scene_image):
    """Find object in scene matching text description."""
    # Detect all objects
    detections = object_detector(scene_image)

    # Filter by CLIP similarity
    best_match = None
    max_score = 0
    for det in detections:
        crop = scene_image[det.bbox]
        score = clip_similarity(crop, description)
        if score > max_score:
            best_match = det
            max_score = score

    return best_match  # Object matching "red cup"

2. Task and Motion Planning (TAMP)​

Challenge: LLM plans high-level tasks, but robot needs low-level motions.

Hierarchy:

High-Level (LLM):     "Grasp the cup"
         ↓
Mid-Level (Planner):  Move arm to pre-grasp pose
         ↓
Low-Level (Control):  Joint trajectories, torques

Example:

# LLM output
llm_plan = ["navigate_to(table)", "grasp(cup)", "navigate_to(user)"]

# Mid-level expansion
for action in llm_plan:
    if action == "grasp(cup)":
        # Motion planning
        cup_pose = perception.get_object_pose("cup")
        pre_grasp = compute_pre_grasp_pose(cup_pose)
        grasp_trajectory = motion_planner.plan(current_pose, pre_grasp)
        execute_trajectory(grasp_trajectory)
        close_gripper()

3. Closed-Loop Execution​

Open-Loop (No Feedback):

LLM → Plan → Execute → Done

Problem: Fails if environment changes.

Closed-Loop (VLA):

LLM → Plan → Execute → Observe → Replan (if needed) → Execute...

Implementation:

def execute_with_feedback(llm_plan):
    for step in llm_plan:
        # Execute
        result = execute_action(step)

        # Check success
        success = verify_action(step)

        if not success:
            # Ask LLM to replan
            error_context = f"Failed: {step}. Current state: {get_state()}"
            new_plan = llm.replan(error_context, remaining_steps)
            return execute_with_feedback(new_plan)

VLA Model Examples​

1. RT-1 & RT-2 (Google DeepMind)​

RT-2 = Robotics Transformer 2

Architecture: Vision Transformer + Language Model → Action Tokens

Training:

  • 13B parameter VLM
  • Trained on web data + robot demonstrations
  • Outputs discretized actions (robot movements)

Capabilities:

  • Zero-shot generalization to new objects
  • Reasoning: "Pick up the extinct animal" → Selects dinosaur toy
  • Multimodal understanding

Limitation: Requires expensive training on robot data.

2. PaLM-E (Google)​

PaLM-E = Embodied multimodal LLM (562B parameters)

Input: Text + Images → Output: Text (plans) or Actions

Example:

Input: [Image of table], "How many objects are blue?"
Output: "There are 2 blue objects: a cup and a block."

Robotics: Can directly output low-level actions for mobile manipulation.

3. SayCan (Google)​

SayCan = "Do as I can, not as I say"

Idea: Ground LLM plans in robot's actual capabilities (affordances).

Method:

  1. LLM generates candidate actions
  2. Value function scores feasibility (can robot do it?)
  3. Select highest-scoring feasible action
  4. Repeat

Example:

Task: "Bring me a soda"
LLM candidates: ["open fridge", "grasp soda", "navigate to user"]
Affordance scores: [0.9, 0.7, 0.95]  # Robot CAN open fridge, might fail grasp
Selected: "open fridge" (highest feasible)

4. Code as Policies (Google)​

Idea: LLM generates Python code to control robot.

Advantages:

  • Leverages LLM's code generation ability
  • Interpretable (humans can read the code)
  • Flexible (full Python expressiveness)

Example:

# LLM-generated code
def task_bring_cup():
    """Bring the cup on the table to the user."""
    # Navigate to table
    robot.navigate_to("table")

    # Detect cup using vision
    cup_pos = robot.detect_object("cup")

    # Grasp
    robot.move_gripper_to(cup_pos)
    robot.close_gripper()

    # Deliver
    robot.navigate_to("user")
    robot.open_gripper()

We'll use this approach in this module!

Challenges and Solutions​

Challenge 1: Hallucinations​

Problem: LLMs confidently generate invalid plans.

Example:

User: "Fly to the moon"
LLM: [navigate_to("moon"), land()]  # Robot can't fly!

Solutions:

  • Action libraries: Constrain LLM to valid actions
  • Affordance checking: Verify actions are feasible
  • Human-in-the-loop: Approve plans before execution

Challenge 2: Grounding Errors​

Problem: LLM misidentifies objects in vision.

Example:

User: "Grasp the apple"
LLM plan: grasp(object_id=3)  # But object_id=3 is an orange!

Solutions:

  • Vision-Language models: CLIP, BLIP for accurate grounding
  • Verification: Show image to LLM: "Is this an apple?" before grasping
  • Multi-modal prompts: Include images in LLM context

Challenge 3: Safety​

Problem: LLM might generate unsafe actions.

Example:

LLM: [move_arm(velocity=1000)]  # Too fast! Dangerous!

Solutions:

  • Safety constraints: Enforce velocity/force limits
  • Sandboxing: Test plans in simulation first
  • E-stop integration: Hardware kill switch

Challenge 4: Latency​

Problem: LLM inference takes seconds (too slow for real-time control).

Solutions:

  • Hierarchical planning: LLM plans high-level, fast controllers execute
  • Local models: Run smaller LLMs on-robot (LLaMA 3)
  • Caching: Pre-compute plans for common tasks

Summary​

VLA represents a paradigm shift:

  • Language as interface: Natural communication with robots
  • LLMs for reasoning: High-level task planning
  • Grounding: Connect language to vision and actions
  • Closed-loop: Observe → Replan → Adapt

Key Insight: Robots don't need to be programmed for every task. They can reason about tasks using LLMs.

Next: Implement voice commands using OpenAI Whisper!

Key Takeaways
  • VLA: Vision + Language + Action = Multimodal robot intelligence
  • LLMs for Planning: GPT-4, Claude generate task plans from language
  • Grounding: Connect words ("red cup") to perception (camera detections)
  • TAMP: Task planning (LLM) + Motion planning (traditional)
  • Closed-Loop: Execute → Observe → Replan
  • Code as Policies: LLM generates executable Python code
  • Challenges: Hallucinations, safety, latency → need guardrails
