# URDF for Humanoid Robots

## Learning Objectives

By the end of this chapter, you will be able to:

- Explain what URDF is and why robots need a description format
- Define links (rigid bodies) and joints (connections) in XML
- Build a simple humanoid URDF model from scratch
- Visualize URDF models in RViz2
- Use Xacro macros to create modular, reusable robot descriptions

## What is URDF?

**URDF** (Unified Robot Description Format) is an XML format that describes a robot's physical structure — its body parts, how they connect, and how they move.

Every tool in the ROS 2 ecosystem uses URDF:
- **Gazebo** reads it to simulate physics
- **RViz2** reads it to visualize the robot
- **MoveIt 2** reads it to plan motion
- **Isaac Sim** can import it for photorealistic simulation

:::info Think of URDF as the Robot's Blueprint
Just as an architect uses blueprints to describe a building's structure, roboticists use URDF to describe a robot's body. Without it, no simulator or planning tool can understand your robot.
:::

## URDF Fundamentals

A URDF model consists of two primary elements:

### Links (Rigid Bodies)

A **link** is a rigid body part — a torso, an arm segment, a foot:

```xml
<link name="torso">
  <!-- What the link looks like (for visualization) -->
  <visual>
    <geometry>
      <box size="0.3 0.2 0.5"/>
    </geometry>
    <material name="blue">
      <color rgba="0.2 0.3 0.8 1.0"/>
    </material>
  </visual>

  <!-- Physical collision boundary -->
  <collision>
    <geometry>
      <box size="0.3 0.2 0.5"/>
    </geometry>
  </collision>

  <!-- Mass and inertia for physics simulation -->
  <inertial>
    <mass value="10.0"/>
    <inertia ixx="0.1" ixy="0.0" ixz="0.0"
             iyy="0.1" iyz="0.0" izz="0.05"/>
  </inertial>
</link>
```

Each link has three optional components:

| Component | Purpose | Required for |
|-----------|---------|-------------|
| `<visual>` | How it looks | RViz2, Isaac Sim |
| `<collision>` | Physics boundary | Gazebo collision detection |
| `<inertial>` | Mass and inertia | Gazebo dynamics simulation |

### Joints (Connections)

A **joint** connects two links and defines how they move relative to each other:

```xml
<joint name="left_hip_pitch" type="revolute">
  <parent link="torso"/>
  <child link="left_upper_leg"/>
  <origin xyz="0.1 -0.1 -0.25" rpy="0 0 0"/>
  <axis xyz="0 1 0"/>
  <limit lower="-1.57" upper="1.57" effort="100" velocity="2.0"/>
</joint>
```

### Joint Types

| Type | Motion | DOF | Example |
|------|--------|-----|---------|
| `revolute` | Rotation with limits | 1 | Elbow, knee |
| `continuous` | Unlimited rotation | 1 | Wheel |
| `prismatic` | Linear sliding | 1 | Telescope arm |
| `fixed` | No motion | 0 | Camera mount |
| `floating` | Free in space | 6 | Mobile base |
| `planar` | 2D translation | 2 | XY table |

## Building a Simple Humanoid

Let's build a minimal humanoid with a torso, head, and two legs:

```xml
<?xml version="1.0"?>
<robot name="simple_humanoid" xmlns:xacro="http://www.ros.org/wiki/xacro">

  <!-- ==================== TORSO ==================== -->
  <link name="base_link">
    <visual>
      <geometry><box size="0.3 0.15 0.4"/></geometry>
      <material name="silver">
        <color rgba="0.7 0.7 0.75 1.0"/>
      </material>
    </visual>
    <collision>
      <geometry><box size="0.3 0.15 0.4"/></geometry>
    </collision>
    <inertial>
      <mass value="8.0"/>
      <inertia ixx="0.08" ixy="0" ixz="0"
               iyy="0.08" iyz="0" izz="0.04"/>
    </inertial>
  </link>

  <!-- ==================== HEAD ==================== -->
  <link name="head">
    <visual>
      <geometry><sphere radius="0.1"/></geometry>
      <material name="dark_grey">
        <color rgba="0.3 0.3 0.35 1.0"/>
      </material>
    </visual>
```

## Visualizing in RViz2

```bash
# Install necessary packages
sudo apt install ros-humble-joint-state-publisher-gui ros-humble-robot-state-publisher

# Launch RViz2 with your URDF
ros2 launch urdf_tutorial display.launch.py \
    model:=/path/to/simple_humanoid.urdf
```

The `joint_state_publisher_gui` provides sliders to move each joint interactively.

## Xacro: Modular Robot Descriptions

Real humanoid URDFs can be thousands of lines. **Xacro** (XML Macros) makes them manageable:

### Defining a Reusable Leg Macro

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="humanoid">

  <!-- Parameters -->
  <xacro:property name="upper_leg_length" value="0.3"/>
  <xacro:property name="lower_leg_length" value="0.3"/>
  <xacro:property name="leg_radius" value="0.04"/>

  <!-- Reusable leg macro -->
  <xacro:macro name="leg" params="side x_offset">
    <link name="${side}_upper_leg">
      <visual>
        <origin xyz="0 0 ${-upper_leg_length/2}"/>
        <geometry>
          <cylinder radius="${leg_radius}" length="${upper_leg_length}"/>
        </geometry>
      </visual>
      <inertial>
        <mass value="3.0"/>
        <inertia ixx="0.025" ixy="0" ixz="0"
                 iyy="0.025" iyz="0" izz="0.002"/>
      </inertial>
    </link>

    <joint name="${side}_hip" type="revolute">
      <parent link="base_link"/>
      <child link="${side}_upper_leg"/>
      <origin xyz="${x_offset} 0 -0.2"/>
      <axis xyz="0 1 0"/>
      <limit lower="-1.57" upper="1.57" effort="80" velocity="2.0"/>
    </joint>

    <link name="${side}_lower_leg">
      <visual>
        <origin xyz="0 0 ${-lower_leg_length/2}"/>
        <geometry>
          <cylinder radius="${leg_radius * 0.9}" length="${lower_leg_length}"/>
        </geometry>
      </visual>
      <inertial>
        <mass value="2.0"/>
        <inertia ixx="0.015" ixy="0" ixz="0"
                 iyy="0.015" iyz="0" izz="0.001"/>
      </inertial>
    </link>

    <joint name="${side}_knee" type="revolute">
      <parent link="${side}_upper_leg"/>
      <child link="${side}_lower_leg"/>
      <origin xyz="0 0 ${-upper_leg_length}"/>
      <axis xyz="0 1 0"/>
      <limit lower="0" upper="2.5" effort="80" velocity="2.0"/>
    </joint>
  </xacro:macro>

  <!-- Use the macro for both legs -->
  <xacro:leg side="left" x_offset="0.08"/>
  <xacro:leg side="right" x_offset="-0.08"/>

</robot>
```

### Processing Xacro Files

```bash
# Convert xacro to URDF
xacro humanoid.urdf.xacro > humanoid.urdf

# Check URDF validity
check_urdf humanoid.urdf

# View link/joint tree
urdf_to_graphviz humanoid.urdf
```

:::tip Xacro Best Practices
- Use `xacro:property` for dimensions that appear in multiple places
- Use `xacro:macro` for repeated structures (arms, legs, fingers)
- Keep one macro per file and `xacro:include` them into the main file
- Always test with `check_urdf` after changes
:::

## Kinematic Chains

A humanoid robot is a **tree of kinematic chains** rooted at the base:

```
                    base_link (torso)
                   /     |      \
              head    left_arm   right_arm
                      /            \
              left_upper_arm    right_upper_arm
                    |                |
              left_forearm      right_forearm
                    |                |
              left_hand          right_hand
              
              left_upper_leg   right_upper_leg
                    |                |
              left_lower_leg   right_lower_leg
                    |                |
              left_foot          right_foot
```

Each path from root to leaf is a kinematic chain. For a humanoid, there are typically:
- **2 arm chains** (shoulder → elbow → wrist → hand)
- **2 leg chains** (hip → knee → ankle → foot)
- **1 head chain** (neck → head)

The total degrees of freedom (DOF) for a humanoid typically ranges from **20 to 50+** depending on hand and finger articulation.

## Summary

| Concept | Description |
|---------|-------------|
| **URDF** | XML format describing robot structure |
| **Link** | Rigid body with visual, collision, and inertial properties |
| **Joint** | Connection between two links defining motion type |
| **Xacro** | Macro system for modular, parameterized URDF files |
| **Kinematic chain** | Series of links and joints from root to end-effector |
| **RViz2** | Visualization tool for inspecting URDF models |

1. **Build a URDF**: Create a URDF for a simple robot arm with 3 revolute joints. Visualize it in RViz2 using `joint_state_publisher_gui`.

2. **Add a camera**: Extend the simple humanoid URDF with a fixed camera joint on the head. Add a `<visual>` box to represent the camera.

3. **Xacro refactor**: Take the full humanoid URDF and refactor it using Xacro macros. Create separate macros for `leg` and `arm`, parameterized by side (left/right).

4. **Inspect a real humanoid**: Download the URDF for an open-source humanoid (e.g., Unitree H1 or NAO) and explore its structure with `check_urdf` and `urdf_to_graphviz`.

5. **DOF analysis**: Count the total degrees of freedom in the simple humanoid URDF. How many joints are revolute? What's the kinematic chain from `base_link` to `left_lower_leg`?
