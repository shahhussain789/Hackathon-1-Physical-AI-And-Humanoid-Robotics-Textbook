Robot Models: URDF & SDF

Learning Objectives​

By the end of this chapter, you will be able to:

  • Explain the difference between URDF and SDF and when to use each
  • Build a robot model from scratch with links, joints, and physical properties
  • Define collision geometry separate from visual geometry for performance
  • Add meshes and materials for realistic rendering
  • Calculate and specify inertial properties (mass, inertia tensor)
  • Import and test existing humanoid models in Gazebo
  • Debug common model-building errors

Why Robot Description Matters​

Before you can simulate a robot, you need to describe its physical structure to the simulator: What does it look like? How are its parts connected? How much does each part weigh? What are its joint limits?

This description is the robot's model file -- the blueprint that Gazebo (and ROS 2) use to create the virtual twin.

Two formats dominate robotics:

  • URDF (Unified Robot Description Format): The ROS standard
  • SDF (Simulation Description Format): Gazebo's native format

Understanding both is essential because you will encounter both in real-world projects.

URDF: The ROS Standard​

What is URDF?​

URDF is an XML format created by the ROS community to describe robot geometry, kinematics, and basic physical properties. Nearly every robot with ROS support ships with a URDF file.

URDF Structure​

A URDF file describes a robot as a tree of links connected by joints:

robot
  link (base_link)
    joint (joint1) -> link (link1)
      joint (joint2) -> link (link2)
        joint (joint3) -> link (link3)
Tree Topology Only

URDF supports only tree structures (no loops). This means you cannot directly model a four-bar linkage or a parallel mechanism in URDF. SDF supports closed-loop kinematic chains. For most humanoid models (serial chains for arms and legs), URDF works fine.

Building a Simple Robot Arm​

Let's build a 2-link robot arm step by step.

Step 1: Define the Robot and Base Link​

<?xml version="1.0"?>
<robot name="simple_arm" xmlns:xacro="http://www.ros.org/wiki/xacro">

  <!-- Base link: fixed to the world -->
  <link name="base_link">
    <visual>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
      <material name="gray">
        <color rgba="0.5 0.5 0.5 1.0"/>
      </material>
    </visual>
    <collision>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="5.0"/>
      <inertia ixx="0.013" ixy="0" ixz="0"
               iyy="0.013" iyz="0" izz="0.025"/>
    </inertial>
  </link>

</robot>

Each link has three key elements:

  • <visual>: What you see in the GUI (geometry + material)
  • <collision>: What the physics engine uses for contact detection
  • <inertial>: Mass and inertia tensor for dynamics

Step 2: Add the First Arm Segment​

  <!-- First arm segment -->
  <link name="upper_arm">
    <visual>
      <origin xyz="0 0 0.25" rpy="0 0 0"/>
      <geometry>
        <cylinder radius="0.04" length="0.5"/>
      </geometry>
      <material name="blue">
        <color rgba="0.2 0.2 0.8 1.0"/>
      </material>
    </visual>
    <collision>
      <origin xyz="0 0 0.25" rpy="0 0 0"/>
      <geometry>
        <cylinder radius="0.04" length="0.5"/>
      </geometry>
    </collision>
    <inertial>
      <origin xyz="0 0 0.25" rpy="0 0 0"/>
      <mass value="2.0"/>
      <inertia ixx="0.043" ixy="0" ixz="0"
               iyy="0.043" iyz="0" izz="0.0016"/>
    </inertial>
  </link>

  <!-- Joint connecting base to upper arm -->
  <joint name="shoulder_joint" type="revolute">
    <parent link="base_link"/>
    <child link="upper_arm"/>
    <origin xyz="0 0 0.025" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>  <!-- Rotate around Y axis -->
    <limit lower="-1.57" upper="1.57"
           effort="100" velocity="1.0"/>
  </joint>

Step 3: Add the Second Arm Segment​

  <!-- Forearm -->
  <link name="forearm">
    <visual>
      <origin xyz="0 0 0.2" rpy="0 0 0"/>
      <geometry>
        <cylinder radius="0.03" length="0.4"/>
      </geometry>
      <material name="light_blue">
        <color rgba="0.4 0.6 0.9 1.0"/>
      </material>
    </visual>
    <collision>
      <origin xyz="0 0 0.2" rpy="0 0 0"/>
      <geometry>
        <cylinder radius="0.03" length="0.4"/>
      </geometry>
    </collision>
    <inertial>
      <origin xyz="0 0 0.2" rpy="0 0 0"/>
      <mass value="1.0"/>
      <inertia ixx="0.014" ixy="0" ixz="0"
               iyy="0.014" iyz="0" izz="0.00045"/>
    </inertial>
  </link>

  <joint name="elbow_joint" type="revolute">
    <parent link="upper_arm"/>
    <child link="forearm"/>
    <origin xyz="0 0 0.5" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit lower="0" upper="2.36"
           effort="50" velocity="1.5"/>
  </joint>

</robot>

Save this as simple_arm.urdf. To visualize it in ROS 2:

# Install the joint state publisher GUI
sudo apt-get install -y ros-humble-joint-state-publisher-gui \
                        ros-humble-robot-state-publisher \
                        ros-humble-rviz2

# Launch RViz with the URDF
ros2 launch robot_state_publisher robot_state_publisher.launch.py \
  urdf:=simple_arm.urdf

URDF Joint Types​

URDF supports several joint types:

Joint TypeDescriptionDOF
revoluteRotates around an axis with limits1
continuousRotates around an axis without limits (wheels)1
prismaticSlides along an axis with limits1
fixedNo motion (rigidly attaches child to parent)0
floating6-DOF free motion (rarely used directly)6
planarMotion in a plane2

For humanoid robots, you will primarily use revolute joints (for elbows, knees, shoulders) and fixed joints (for rigidly attaching sensors or decorative parts).

SDF: Gazebo's Native Format​

Why SDF in Addition to URDF?​

SDF was created because URDF has several limitations:

FeatureURDFSDF
Closed-loop chainsNoYes
Multiple robotsNo (one <robot> per file)Yes
World descriptionNoYes (lights, physics, terrain)
Sensor definitionsLimited (via Gazebo extensions)Native
Nested modelsNoYes
Material PBRNoYes

In practice, most teams write their robot in URDF (for ROS compatibility) and either convert it to SDF or let Gazebo auto-convert at load time.

SDF Model Structure​

Here is the same arm expressed in SDF:

<?xml version="1.0" ?>
<sdf version="1.9">
  <model name="simple_arm">

    <link name="base_link">
      <inertial>
        <mass>5.0</mass>
        <inertia>
          <ixx>0.013</ixx><iyy>0.013</iyy><izz>0.025</izz>
        </inertia>
      </inertial>
      <collision name="collision">
        <geometry>
          <cylinder><radius>0.1</radius><length>0.05</length></cylinder>
        </geometry>
      </collision>
      <visual name="visual">
        <geometry>
          <cylinder><radius>0.1</radius><length>0.05</length></cylinder>
        </geometry>
        <material>
          <ambient>0.5 0.5 0.5 1</ambient>
        </material>
      </visual>
    </link>

    <link name="upper_arm">
      <pose relative_to="shoulder_joint">0 0 0.25 0 0 0</pose>
      <inertial>
        <mass>2.0</mass>
        <inertia>
          <ixx>0.043</ixx><iyy>0.043</iyy><izz>0.0016</izz>
        </inertia>
      </inertial>
      <collision name="collision">
        <geometry>
          <cylinder><radius>0.04</radius><length>0.5</length></cylinder>
        </geometry>
      </collision>
      <visual name="visual">
        <geometry>
          <cylinder><radius>0.04</radius><length>0.5</length></cylinder>
        </geometry>
        <material>
          <ambient>0.2 0.2 0.8 1</ambient>
        </material>
      </visual>
    </link>

    <joint name="shoulder_joint" type="revolute">
      <parent>base_link</parent>
      <child>upper_arm</child>
      <pose relative_to="base_link">0 0 0.025 0 0 0</pose>
      <axis>
        <xyz>0 1 0</xyz>
        <limit>
          <lower>-1.57</lower>
          <upper>1.57</upper>
          <effort>100</effort>
          <velocity>1.0</velocity>
        </limit>
      </axis>
    </joint>

  </model>
</sdf>

Notice the differences: SDF uses nested elements instead of attributes (e.g., <mass>5.0</mass> vs <mass value="5.0"/>), and supports relative_to for pose definitions.

Using Xacro for Modular URDFs​

Real robot models are too complex to write as raw XML. Xacro (XML macros) is a ROS tool that adds programming constructs to URDF:

<?xml version="1.0"?>
<robot name="modular_arm" xmlns:xacro="http://www.ros.org/wiki/xacro">

  <!-- Parameters -->
  <xacro:property name="base_radius" value="0.1"/>
  <xacro:property name="arm_length" value="0.5"/>
  <xacro:property name="arm_radius" value="0.04"/>

  <!-- Macro for computing cylinder inertia -->
  <xacro:macro name="cylinder_inertia" params="mass radius length">
    <inertial>
      <mass value="${mass}"/>
      <inertia ixx="${(1/12)*mass*(3*radius*radius + length*length)}"
               ixy="0" ixz="0"
               iyy="${(1/12)*mass*(3*radius*radius + length*length)}"
               iyz="0"
               izz="${(1/2)*mass*radius*radius}"/>
    </inertial>
  </xacro:macro>

  <!-- Macro for an arm segment -->
  <xacro:macro name="arm_segment" params="name parent length radius mass color">
    <link name="${name}">
      <visual>
        <origin xyz="0 0 ${length/2}" rpy="0 0 0"/>
        <geometry>
          <cylinder radius="${radius}" length="${length}"/>
        </geometry>
        <material name="${name}_color">
          <color rgba="${color}"/>
        </material>
      </visual>
      <collision>
        <origin xyz="0 0 ${length/2}" rpy="0 0 0"/>
        <geometry>
          <cylinder radius="${radius}" length="${length}"/>
        </geometry>
      </collision>
      <xacro:cylinder_inertia mass="${mass}"
                              radius="${radius}"
                              length="${length}"/>
    </link>
  </xacro:macro>

  <!-- Use the macros -->
  <link name="base_link">
    <visual>
      <geometry>
        <cylinder radius="${base_radius}" length="0.05"/>
      </geometry>
    </visual>
  </link>

  <xacro:arm_segment name="upper_arm" parent="base_link"
                     length="${arm_length}" radius="${arm_radius}"
                     mass="2.0" color="0.2 0.2 0.8 1.0"/>

  <joint name="shoulder_joint" type="revolute">
    <parent link="base_link"/>
    <child link="upper_arm"/>
    <origin xyz="0 0 0.025" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit lower="-1.57" upper="1.57" effort="100" velocity="1.0"/>
  </joint>

</robot>

Process Xacro to URDF:

# Convert xacro to URDF
xacro simple_arm.urdf.xacro > simple_arm.urdf

# Verify the output
check_urdf simple_arm.urdf
Xacro Best Practices
  • Use properties for any dimension or parameter you might want to change
  • Use macros for repeated structures (fingers, leg segments)
  • Use includes to split large models across files (one file per limb)
  • Always generate and validate the final URDF before using it in simulation

Adding Meshes and Materials​

Primitive shapes (boxes, cylinders, spheres) are fine for prototyping, but real robots need detailed meshes for visual rendering.

Using Mesh Files​

Gazebo supports STL and COLLADA (.dae) mesh files. OBJ is also supported in newer versions.

<visual name="visual">
  <geometry>
    <mesh>
      <uri>model://my_robot/meshes/upper_arm.dae</uri>
      <scale>0.001 0.001 0.001</scale>  <!-- mm to meters -->
    </mesh>
  </geometry>
</visual>

In URDF, use the package:// URI for ROS packages:

<visual>
  <geometry>
    <mesh filename="package://my_robot_description/meshes/upper_arm.dae"
          scale="0.001 0.001 0.001"/>
  </geometry>
</visual>

Collision Mesh Strategy​

Performance Warning

Never use a detailed visual mesh as the collision mesh. A mesh with 50,000 triangles will make the physics engine extremely slow. Instead:

  1. Use primitive shapes (box, cylinder, sphere) for collision
  2. Or use a simplified convex hull of the visual mesh
  3. Multiple simple collision shapes can approximate complex geometry
<link name="torso">
  <!-- Detailed mesh for rendering -->
  <visual name="visual">
    <geometry>
      <mesh>
        <uri>model://humanoid/meshes/torso_detailed.dae</uri>
      </mesh>
    </geometry>
  </visual>

  <!-- Simple box for collision (fast) -->
  <collision name="collision">
    <geometry>
      <box><size>0.4 0.3 0.6</size></box>
    </geometry>
  </collision>
</link>

Materials in SDF​

SDF supports PBR (Physically Based Rendering) materials:

<visual name="visual">
  <geometry>
    <mesh><uri>model://robot/meshes/arm.dae</uri></mesh>
  </geometry>
  <material>
    <ambient>0.3 0.3 0.3 1</ambient>
    <diffuse>0.7 0.7 0.7 1</diffuse>
    <specular>0.01 0.01 0.01 1</specular>
    <pbr>
      <metal>
        <albedo_map>model://robot/materials/textures/arm_albedo.png</albedo_map>
        <normal_map>model://robot/materials/textures/arm_normal.png</normal_map>
        <metalness>0.6</metalness>
        <roughness>0.4</roughness>
      </metal>
    </pbr>
  </material>
</visual>

Inertial Properties​

Correct inertial properties are critical for realistic simulation. If the inertia tensor is wrong, your robot will behave erratically.

Computing Inertia for Primitives​

For common shapes, the inertia tensor formulas are:

Box (mass m, dimensions w x h x d):

Ixx = (1/12) * m * (h^2 + d^2)
Iyy = (1/12) * m * (w^2 + d^2)
Izz = (1/12) * m * (w^2 + h^2)

Cylinder (mass m, radius r, length l):

Ixx = Iyy = (1/12) * m * (3*r^2 + l^2)
Izz = (1/2) * m * r^2

Sphere (mass m, radius r):

Ixx = Iyy = Izz = (2/5) * m * r^2

Python Helper for Inertia Calculation​

"""Compute inertia tensors for common primitive shapes."""

def box_inertia(mass: float, width: float, height: float, depth: float):
    """Compute inertia tensor for a solid box."""
    ixx = (1/12) * mass * (height**2 + depth**2)
    iyy = (1/12) * mass * (width**2 + depth**2)
    izz = (1/12) * mass * (width**2 + height**2)
    return {"ixx": ixx, "iyy": iyy, "izz": izz}


def cylinder_inertia(mass: float, radius: float, length: float):
    """Compute inertia tensor for a solid cylinder (along Z axis)."""
    ixx = (1/12) * mass * (3 * radius**2 + length**2)
    iyy = ixx
    izz = 0.5 * mass * radius**2
    return {"ixx": ixx, "iyy": iyy, "izz": izz}


def sphere_inertia(mass: float, radius: float):
    """Compute inertia tensor for a solid sphere."""
    val = (2/5) * mass * radius**2
    return {"ixx": val, "iyy": val, "izz": val}


# Example: compute inertia for a 2kg arm segment (cylinder)
arm = cylinder_inertia(mass=2.0, radius=0.04, length=0.5)
print(f"Arm inertia: Ixx={arm['ixx']:.4f}, Iyy={arm['iyy']:.4f}, Izz={arm['izz']:.4f}")
# Output: Arm inertia: Ixx=0.0427, Iyy=0.0427, Izz=0.0016

For Complex Meshes​

For mesh-based links, use MeshLab or the meshlab command-line tool to compute inertia from the mesh geometry, or use the gz sdf tool:

# Gazebo can compute inertia from a mesh
gz sdf --check model.sdf
Common Inertia Mistakes
  1. All zeros: The link will not respond to forces at all
  2. Negative values: Physics engine will produce NaN and the simulation crashes
  3. Wildly incorrect magnitudes: Robot limbs fly apart or collapse
  4. Missing inertial tag: Gazebo treats the link as having zero mass, causing warnings

Always double-check inertia values, especially for humanoid models where incorrect arm or leg inertia leads to unrealistic swinging motion.

Loading a URDF into Gazebo​

To use a URDF-defined robot in Gazebo, you have two options:

Option 1: Let Gazebo auto-convert at runtime (via the ROS-Gazebo bridge, covered in Chapter 4).

Option 2: Convert URDF to SDF manually:

# Convert URDF to SDF
gz sdf -p simple_arm.urdf > simple_arm.sdf

# Verify the converted file
gz sdf --check simple_arm.sdf

Model Directory Structure​

For a well-organized robot model package, follow this structure:

my_robot_description/
  package.xml
  CMakeLists.txt
  urdf/
    my_robot.urdf.xacro      # Main robot description (Xacro)
    my_robot.urdf              # Generated URDF
    includes/
      arm.urdf.xacro          # Arm macro
      leg.urdf.xacro          # Leg macro
      sensors.urdf.xacro      # Sensor attachments
  meshes/
    visual/                    # Detailed meshes for rendering
      torso.dae
      upper_arm.dae
    collision/                 # Simplified meshes for physics
      torso_collision.stl
      upper_arm_collision.stl
  config/
    joint_limits.yaml          # Joint limit parameters
    controllers.yaml           # Controller configuration
  launch/
    display.launch.py          # RViz visualization
    gazebo.launch.py           # Gazebo simulation
  worlds/
    test_world.sdf             # Test world with the robot

Debugging Models​

Common Errors and Fixes​

Problem: Robot links overlap or appear at the origin. Cause: Missing or incorrect <origin> tags in joints. Fix: Verify each joint's <origin> places the child link correctly.

Problem: Robot collapses or explodes on simulation start. Cause: Incorrect inertial properties or overlapping collision geometry. Fix: Check inertia values and ensure collision shapes do not interpenetrate at the initial pose.

Problem: "No valid inertia" warning in Gazebo. Cause: A non-fixed link is missing the <inertial> tag. Fix: Add mass and inertia to every non-static, non-fixed link.

Validation Tools​

# Check URDF syntax
check_urdf my_robot.urdf

# Visualize URDF tree structure
urdf_to_graphiz my_robot.urdf
# This creates a PDF showing the link-joint tree

# Check SDF syntax
gz sdf --check my_model.sdf

Summary​

In this chapter, you learned:

  • URDF: The ROS standard for robot description (tree topology, links + joints)
  • SDF: Gazebo's native format with richer features (closed loops, world descriptions, PBR)
  • Xacro: Templating system for modular, maintainable URDF files
  • Geometry: Visual meshes for rendering, simplified collision shapes for physics
  • Inertial properties: Mass and inertia tensor -- critical for realistic dynamics
  • Existing models: How to find and import standard robot descriptions
