## Case Study 1: Humanoid Arm Reaching

### Scenario

**Task**: Command a 7-DoF humanoid arm to reach a target position while avoiding joint limits.

**Tools**: IK, trajectory generation, PID control, Gazebo simulation

### Step 1: Define Robot Model (URDF)

**Simplified 7-DoF arm** (shoulder 3-DoF, elbow 1-DoF, wrist 3-DoF):
```xml

  <link name="shoulder_link"/>

  <link name="forearm_link"/>
  <link name="wrist_link"/>
  <link name="hand_link"/>

  <joint name="shoulder_pan" type="revolute">
    <limit lower="-3.14" upper="3.14" effort="100" velocity="2"/>
  </joint>
  <!-- Additional joints... -->
</robot>
```

###Step 2: Compute Inverse Kinematics

```python
from scipy.optimize import minimize

def ik_optimization_7dof(target_pos, target_orient, robot_model):
    """IK for 7-DoF arm using optimization."""

    def cost(theta):
        # Forward kinematics
        pos, orient = fk_7dof(theta, robot_model)

        # Position error
        pos_error = np.linalg.norm(pos - target_pos)

        # Orientation error (quaternion distance)
        orient_error = quaternion_distance(orient, target_orient)

        # Secondary objective: Stay near mid-range
        mid_range = (robot_model.joint_limits_lower + robot_model.joint_limits_upper) / 2
        config_cost = 0.1 * np.linalg.norm(theta - mid_range)

        return pos_error + orient_error + config_cost

    # Joint limits as bounds
    bounds = [(robot_model.joint_limits_lower[i], robot_model.joint_limits_upper[i])
              for i in range(7)]

    result = minimize(cost, x0=robot_model.current_joint_angles, bounds=bounds, method='SLSQP')

    return result.x if result.success else None
```

### Step 3: Generate Trajectory

```python
def generate_reaching_trajectory(start_theta, goal_theta, duration=2.0, dt=0.01):
    """Generate smooth joint trajectory using 5th-order polynomial."""
    num_steps = int(duration / dt)
    trajectory = []

    for joint_idx in range(len(start_theta)):
        joint_traj = []
        for step in range(num_steps):
            t = step * dt
            theta = quintic_polynomial(t, duration, start_theta[joint_idx], goal_theta[joint_idx])
            joint_traj.append(theta)
        trajectory.append(joint_traj)

    return np.array(trajectory).T  # Shape: (num_steps, num_joints)
```

### Step 4: Execute with PID Control (Gazebo)

```python
import rclpy
from std_msgs.msg import Float64MultiArray

class ReachingController:
    def __init__(self):
        self.node = rclpy.create_node('reaching_controller')
        self.joint_cmd_pub = self.node.create_publisher(
            Float64MultiArray, '/joint_group_effort_controller/commands', 10
        )
        self.pids = [PIDController(kp=50, ki=1, kd=5) for _ in range(7)]

    def execute_trajectory(self, trajectory):
        for target_angles in trajectory:
            current_angles = self.get_joint_states()  # From /joint_states topic

            # Compute control for each joint
            efforts = []
            for i, (target, current, pid) in enumerate(zip(target_angles, current_angles, self.pids)):
                error = target - current
                effort = pid.update(error)
                efforts.append(effort)

            # Publish joint efforts
            msg = Float64MultiArray(data=efforts)
            self.joint_cmd_pub.publish(msg)

            rclpy.spin_once(self.node, timeout_sec=0.01)
```

### Results

**Metrics**:
- **Tracking error**: &lt;2cm position error, &lt;5° orientation error
- **Execution time**: 2 seconds (matches planned duration)
- **Joint limits**: All joints stay within bounds

**Visualization**: In RViz, watch arm smoothly reach target.

## Case Study 2: Bipedal Walking with ZMP

### Scenario

**Task**: Generate a stable walking gait for a humanoid robot using Zero-Moment Point (ZMP) control.

**Background**: ZMP is a stability criterion—robot is stable if ZMP stays inside support polygon (footprint).

### Step 1: Define Gait Parameters

```python
class GaitParameters:
    def __init__(self):
        self.step_length = 0.2  # meters
        self.step_width = 0.1   # lateral separation
        self.step_height = 0.05  # foot clearance
        self.step_duration = 0.8  # seconds per step
        self.double_support_ratio = 0.2  # fraction in double support
```

### Step 2: Generate Foot Trajectories

```python
def generate_footsteps(num_steps, gait_params):
    """Generate sequence of footstep positions."""
    footsteps = []
    x, y = 0, 0

    for i in range(num_steps):
        # Alternate left/right
        lateral_offset = gait_params.step_width / 2 * (1 if i % 2 == 0 else -1)
        x += gait_params.step_length
        footsteps.append({'x': x, 'y': lateral_offset, 'foot': 'left' if i % 2 == 0 else 'right'})

    return footsteps
```

### Step 3: ZMP Preview Control

**Simplified ZMP controller** (linear inverted pendulum model):
```python
def zmp_preview_control(current_com, desired_zmp, params):
    """Compute CoM acceleration to track desired ZMP."""
    g = 9.81
    z_com = params.com_height  # Assume constant CoM height

    # ZMP equation: x_zmp = x_com - (z_com/g) * x_com_ddot
    # Rearranging: x_com_ddot = (g/z_com) * (x_com - x_zmp)

    com_accel = (g / z_com) * (current_com - desired_zmp)
    return com_accel
```

### Step 4: Inverse Kinematics for Leg Configuration

```python
def compute_leg_ik(foot_position, com_position, robot_model):
    """IK to compute joint angles for both legs."""
    # Simplified: Assume planar kinematics
    # In reality, use 6-DoF IK for hip, knee, ankle

    left_leg_angles = ik_6dof_leg(com_position, foot_position['left'], robot_model)
    right_leg_angles = ik_6dof_leg(com_position, foot_position['right'], robot_model)

    return left_leg_angles, right_leg_angles
```

### Step 5: Simulation (Gazebo)

```python
class WalkingController:
    def __init__(self):
        self.gait_params = GaitParameters()
        self.footsteps = generate_footsteps(10, self.gait_params)
        self.current_step = 0

    def update(self, dt):
        # Get current robot state
        com_position = self.get_com_position()
        foot_positions = self.get_foot_positions()

        # Compute desired ZMP (middle of support polygon)
        desired_zmp = self.compute_desired_zmp(self.current_step)

        # ZMP control
        com_accel = zmp_preview_control(com_position, desired_zmp, self.gait_params)

        # Update CoM
        self.com_velocity += com_accel * dt
        new_com = com_position + self.com_velocity * dt

        # IK for legs
        left_angles, right_angles = compute_leg_ik(foot_positions, new_com, self.robot_model)

        # Send commands
        self.publish_joint_commands(left_angles + right_angles)
```

### Results

**Metrics**:
- **Step success rate**: 95% (robot completes 9.5/10 steps without falling)
- **ZMP tracking**: Stays within support polygon 98% of time
- **Walking speed**: 0.25 m/s

**Challenges**:
- Transition from double to single support (brief instability)
- Foot scuffing if step height too low

## Case Study 3: Whole-Body Coordination

### Scenario

**Task**: Humanoid walks forward while reaching for an object with its arm—simultaneous locomotion + manipulation.

**Challenge**: Coordinate 30+ joints without conflict.

### Approach: Hierarchical Control

**Level 1: High-Level Planner**
- Decides: "Walk to position X, reach for object at height Y"

**Level 2: Task Decomposition**
- **Locomotion task**: Generate foot trajectories
- **Manipulation task**: Compute arm IK for reaching

**Level 3: Whole-Body IK**
- Solve for all joint angles that satisfy both tasks
- Use **weighted task priorities** or **null-space projection**

### Null-Space Projection

**Idea**: Primary task (walking) takes priority, secondary task (reaching) uses null space.

```python
def whole_body_ik(primary_task_jacobian, primary_task_error,
                  secondary_task_jacobian, secondary_task_error):
    """Resolve two tasks using null-space projection."""

    # Primary task
    J1 = primary_task_jacobian
    e1 = primary_task_error
    theta_dot_primary = np.linalg.pinv(J1) @ e1

    # Null-space of primary task
    N1 = np.eye(J1.shape[1]) - np.linalg.pinv(J1) @ J1

    # Secondary task (projected into null space)
    J2 = secondary_task_jacobian
    e2 = secondary_task_error
    theta_dot_secondary = N1 @ np.linalg.pinv(J2 @ N1) @ (e2 - J2 @ theta_dot_primary)

    # Combined motion
    theta_dot = theta_dot_primary + theta_dot_secondary
    return theta_dot
```

### Simulation Results

**Metrics**:
- **Walking maintained**: Stable gait despite arm motion
- **Reaching accuracy**: Arm reaches target ±3cm
- **Computational cost**: 5ms per control loop (200 Hz feasible)

**Visualization**: Robot walks forward, extends arm, grasps object, continues walking.

## Debugging Tips

### Common Simulation Issues

| Issue | Symptom | Fix |
|-------|---------|-----|
| **Robot falls immediately** | Unstable at spawn | Check initial joint configuration, add grippers to ground initially |
| **Jittery motion** | Oscillations, vibrations | Reduce PID gains, add damping to joints |
| **IK fails** | Unreachable targets | Check workspace limits, use better initial guess |
| **Slow simulation** | &lt;1× real-time | Reduce physics accuracy, simplify collision meshes |

### Validation Checklist

Before deploying to real hardware:
- [ ] Simulation runs at ≥1× real-time
- [ ] Robot completes task 90%+ success rate (100 trials)
- [ ] Joint torques stay within hardware limits
- [ ] No self-collisions detected
- [ ] Behavior matches expectations (record video, review)

## Transition to Real Hardware

### Sim-to-Real Considerations

**Simulation assumes perfect**:
- Motors (instant torque response)
- Sensors (no noise, no latency)
- Friction (simplified models)

**Real robots have**:
- Motor backlash, gear compliance
- Sensor noise, calibration errors
- Floor variations (carpet vs. tile)

**Mitigation**:
1. **Add realism to simulation**: Sensor noise, actuator delay
2. **Robust control**: High-gain feedback, disturbance rejection
3. **Domain randomization**: Train on varied conditions (Module 4)
4. **Fine-tuning**: Adjust gains on real robot
